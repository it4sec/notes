## Summary

Andrew Ng argues that **agentic workflows**—systems in which language models iteratively plan, act, evaluate, use tools, and revise their outputs—could produce major improvements in AI capability. He suggests that these workflow improvements may, in some applications, have an impact comparable to or greater than simply waiting for the next generation of foundation models.

The central contrast is between a conventional, non-agentic interaction and an agentic process. In a conventional workflow, a user asks a language model for an answer and receives a single response. Ng compares this to asking a person to write an essay from beginning to end without using backspace. An agentic workflow instead breaks the task into stages: outlining, deciding whether web research is needed, gathering information, drafting, reviewing, revising, and iterating.

Ng emphasizes that this iterative structure can substantially improve results. He cites an analysis using OpenAI’s **HumanEval** coding benchmark. According to the transcript, GPT-3.5 achieved 48% accuracy with zero-shot prompting, while GPT-4 achieved 67%. When an agentic workflow was wrapped around GPT-3.5, it reportedly outperformed GPT-4 in the cited comparison. The implication is that better orchestration and reasoning loops can sometimes compensate for differences in base-model capability.

The presentation organizes current agentic systems into four broad design patterns:

1. **Reflection**
2. **Tool use**
3. **Planning**
4. **Multi-agent collaboration**

Ng presents reflection and tool use as relatively robust and immediately useful, while planning and multi-agent collaboration are described as more emerging, powerful, and sometimes unreliable. He recommends that engineers experiment with these patterns because they can provide rapid productivity gains.

He also identifies several broader system-level implications. Agentic systems may need to operate for minutes or hours rather than respond immediately. Fast token generation becomes especially valuable because iterative workflows require many model calls and generate large amounts of intermediate text. Consequently, a faster but somewhat weaker model may outperform a slower, stronger model when placed inside an effective agentic loop.

Ng concludes that agentic workflows could expand the range of tasks AI systems can perform and represent a small but meaningful step toward AGI, which he characterizes as a long journey rather than a single destination.

## Technical innovation and authors’ ideas

### 1. Replacing single-pass generation with iterative computation

The main technical idea is to treat language-model generation as an iterative computational process rather than a single prompt-response event. The system can:

- Decompose the task
- Perform research
- Generate an initial result
- Inspect its own output
- Identify errors or weaknesses
- Revise the result
- Repeat the process as necessary

This changes the role of the language model from a one-shot generator into a component inside a larger reasoning workflow.

### 2. Reflection and self-correction

A reflection workflow feeds a model’s own output back to it with instructions to evaluate correctness, efficiency, structure, or quality. For code generation, the model can:

1. Write code for a specified task.
2. Review the code for bugs and construction issues.
3. Produce corrective feedback.
4. Generate a revised version.
5. Run unit tests.
6. Diagnose test failures.
7. Iterate toward another version.

Ng presents this as a relatively robust technique that often improves performance, although improvement is not guaranteed.

### 3. Separating coding and critique roles

A natural extension of reflection is to use two agents:

- A **coder agent** that writes the code
- A **critic or code-review agent** that evaluates it

The agents can use the same underlying language model but receive different role instructions. This separation creates a general-purpose workflow in which one model instance produces an artifact and another evaluates it, potentially improving reliability and performance.

### 4. Tool use as capability expansion

Tools allow language models to go beyond text generation. The model can generate and execute code or call external capabilities for:

- Analysis
- Information gathering
- Taking actions
- Personal productivity
- Image generation
- Object detection
- Other image manipulation tasks

Ng notes that early tool-use research was particularly prominent in computer vision because language models previously could not directly work with images. Tool calls therefore function as an interface through which a model can access capabilities it does not possess natively.

### 5. Planning and dynamic task decomposition

Planning agents determine a sequence of actions required to complete a complex task. Ng gives an image-processing example involving transforming an image according to a textual instruction. The agent may need to:

1. Determine the pose of a person in the image.
2. Select an appropriate model, potentially from Hugging Face.
3. Use a pose-transfer or image-synthesis model.
4. Apply image-to-text processing.
5. Use text-to-speech or another downstream capability.

The innovation is not merely calling tools, but dynamically deciding which tools and intermediate steps are needed. Ng describes such systems as impressive when they work, but still “finicky” and not consistently reliable.

### 6. Recovery from failure through agentic loops

Iterative loops can allow an agent to respond to failures rather than terminate immediately. Ng describes demonstrations in which an agent encounters an unsuccessful step and reroutes around the failure. This suggests a workflow in which errors become feedback for replanning rather than final system failures.

### 7. Multi-agent collaboration

Multi-agent systems assign different roles to different model instances. In the example of ChatDev, agents may act as:

- CEO
- Software engineer
- Designer
- Product manager
- Tester

These agents communicate through an extended conversation to develop, test, and refine a software project. Ng reports that such systems can sometimes produce surprisingly complex programs, although their reliability remains inconsistent.

### 8. Multi-agent debate

Another proposed pattern is to have multiple agents debate an issue or solution. The agents may even be based on different models, such as ChatGPT and Gemini. Ng presents debate as a design pattern that can improve performance by requiring agents to challenge or evaluate one another’s outputs.

## Key technical ideas

- **Agentic workflow:** Use language models in iterative loops involving planning, action, evaluation, and revision.
- **Reflection:** Ask a model to inspect and improve its own previous output.
- **Test-driven iteration:** Run unit tests, analyze failures, and use the results to generate improved code.
- **Role specialization:** Separate generation and critique into coder and reviewer agents.
- **Tool augmentation:** Let models call external functions, execute code, search, analyze data, manipulate images, and take actions.
- **Planning:** Dynamically select and order tools and subtasks to solve complex problems.
- **Failure recovery:** Use feedback from unsuccessful steps to replan and continue.
- **Multi-agent collaboration:** Assign different roles to multiple agents that communicate over an extended workflow.
- **Multi-agent debate:** Have agents critique or debate one another to improve results.
- **Throughput over one-shot quality:** A faster model that can execute more iterations may outperform a stronger but slower model.
- **Longer latency tolerance:** Effective agentic systems may require users to wait minutes or hours for results instead of expecting immediate responses.
- **Workflow-level scaling:** Improvements in orchestration may yield substantial gains even without a new foundation model.

## Limitations and current challenges

Ng distinguishes between techniques that are already relatively dependable and those that remain experimental:

- **Reflection and tool use** are described as broadly useful and comparatively robust.
- **Planning and multi-agent collaboration** can produce striking results but do not work reliably in every case.
- Agentic systems may be computationally expensive because they require repeated model calls and generate many intermediate tokens.
- Users and developers must adapt to longer response times.
- The effectiveness of the workflow depends on the quality of the underlying model, tool interfaces, prompts, evaluation procedures, and recovery mechanisms.
